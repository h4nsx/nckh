# Literature Review Protocol

## 1. Objective

Build a traceable review of prior work relevant to lightweight CNN–Mamba/YOLO object detection, warehouse perception, and edge deployment. The review should establish the closest prior methods and a supportable research gap.

## 2. Search venues

Search relevant scholarly indexes and publisher/repository pages, for example:
- Google Scholar.
- Semantic Scholar.
- IEEE Xplore.
- ACM Digital Library.
- SpringerLink.
- ScienceDirect.
- arXiv, with preprint status clearly recorded.
- Official project/repository documentation for implementation details.

Use the official paper page, DOI page, or author repository as the source of record when possible.

## 3. Search strings

Use combinations and record the date of each search.

- `"YOLO Mamba" object detection`

### Efficiency and edge
- `"lightweight object detection" edge device`
- `"real-time object detection" embedded`
- `"YOLO" quantization edge deployment`
- `"YOLO" structured pruning latency`
- `"hardware-aware" object detection`
- `"Mamba" edge inference latency`

### Domain and data
- `"warehouse object detection"`
- `"warehouse perception" dataset`
- `"forklift pallet person" object detection dataset`
- `PhysicalAI-SmartSpaces`
- `PhysicalAI-Spatial-Intelligence-Warehouse`

## 4. Inclusion criteria

Include a paper if it contributes evidence about at least one of:
- YOLO or other object-detection architecture relevant to the task.
- CNN–Mamba/SSM integration for visual tasks.
- Lightweight detection or model compression.
- Real edge deployment methodology.
- Warehouse/industrial detection datasets or evaluation.
- The selected NVIDIA dataset or a closely related benchmark.

## 5. Exclusion criteria

Usually exclude:
- Unrelated classification-only papers without a transferable method or insight.
- Papers with insufficient methodological detail for the intended comparison.
- Duplicates of the same publication, unless version changes matter.
- Marketing pages presented as if they were peer-reviewed research.
- Claims supported only by an unsourced blog, unless used solely as informal context.

Preprints can be useful but must be labelled as preprints. Do not describe them as peer-reviewed unless verified.

## 7. Screening process

1. Deduplicate by DOI, title, and author list.
2. Screen title and abstract.
3. Read full text for the closest methods.
4. Extract architecture, datasets, metrics, hardware, and limitations.
5. Compare claims across papers.
6. Search citations/references of the closest papers.
7. Search for newer papers that cite the closest methods.
8. Revisit the gap after the new sources are included.

## 8. Required output

The literature review should produce:
- A paper-analysis card for every included source.
- A comparison table.
- A list of closest competing methods.
- A summary of common design choices.
- A list of unresolved or weakly evaluated questions.
- A research-gap statement with citations.
- A list of claims that remain unverified.

## 9. Reporting cut-off

Record the last date on which the literature search was updated. Update the search before submission to catch recent work.
